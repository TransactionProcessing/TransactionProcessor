# Transaction Processor API reference

This reference covers the routes currently registered by `TransactionProcessor` (without host, port, or deployment path prefix). JSON property names are shown in CLR/PascalCase form; wire casing follows the shared serializer defaults configured at runtime. `Guid` values use UUID strings, decimals are JSON numbers, and date/time values are JSON strings accepted by the configured .NET converters.

## Common behavior

- All endpoint groups below, except health checks and the domain-event controller, require authentication and the `ClientCredentialsOnlyPolicy`. Tokens use the configured OpenIddict validation issuer and API audience. Send `Authorization: Bearer <token>`.
- Handler outcomes pass through `ResponseFactory`. Generic success results serialize the mapped response DTO/model listed below. Successful non-generic command results return status-only responses with no JSON body. Failure status and problem bodies are centralized in `Shared.Results.Web` and can vary by result status.
- No pagination parameters are declared by these routes. Query parameters are listed only where the handler signature binds them.
- Nullable DTO fields may be omitted or `null`; the code does not declare per-property validation attributes for these request DTOs.

## Contract enums

`ProductType`, `CalculationType`, and `FeeType` are enum properties in the DTOs. The project does not configure an enum-to-string JSON converter in `JsonSerializerConfiguration`; confirm the deployed serializer defaults before sending enum values as strings. Merchant `SettlementSchedule` and day-of-week keys are likewise enum-backed.

## Source and known contract caveats

- Minimal API handlers infer body binding for their DTO parameters and query binding for unmatched scalar parameters. Only handler parameters explicitly present in the route are path values.
- The settlement GET-by-ID route handler accepts `merchantId` in addition to `estateId` and `settlementId`; it is not part of the route template and is therefore a query parameter.
- The primary transaction receipt route similarly binds `estateId` as a query parameter because it is omitted from that route. A legacy route carries both IDs in its path.
- `DomainEventController.GetDomainEvent` expects `eventType` in a header and the body to serialize as the dynamically selected domain-event type. Its invalid/unrecognized-event paths are not represented as a stable response DTO.
- Some command success bodies are produced indirectly by `ResponseFactory` and business result types, rather than an endpoint-specific response mapping. Those are documented as result-factory responses instead of guessing a DTO.
